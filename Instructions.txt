EDIT DIRECTLY ON YOUR WEBSITE

ONE-TIME INSTALLATION
Upload all three website files from this folder to the root of your GitHub repository:
- cms-content.js
- inline-editor.js
- inline-editor.css
https://github.com/vivianongjy/vivianongjy.github.io/upload/main
Commit and wait for GitHub Pages to finish publishing. Refresh your website.
Do not replace content JSON, photos, or posts for this update.

EVERYDAY USE
1. Open the page you want to change.
2. Select Edit this page in the footer.
3. Enter the same GitHub access key as your posting desk. If you have not created it yet, use Create a repository access key in the sign-in dialog and follow the permission instructions shown there.
4. Click outlined text and type your changes directly.
5. Click a homepage circle to edit its photo, label and pop-up message. Click the About me photo or its replacement button to change it.
6. On Personal, use Edit stage photos or Add memory here in each life stage. On section pages, use Edit memory or Add a memory where the memories appear.
7. Click a contact circle to edit it; use Add circle or Add contact section to add more. Home and Let’s connect share this contact list.
8. Appearance & song changes the background, panel opacity and song link.
9. Apply in a dialog previews changes. Save changes in the toolbar commits them to GitHub. Your public website updates after GitHub Pages finishes publishing.
10. Exit / discard leaves Edit mode. Confirming discard removes unsaved edits and reloads the normal page.

PRIVACY AND SAVING
Visitors see the normal page and the Edit this page entry button. Editing controls appear only after the editor verifies Vivian’s GitHub account and reads the repository with the supplied key. Real save authorization is enforced by GitHub.
The access key stays in this tab’s memory. It is not stored in localStorage, cookies, exported files, or website content. Reloading or exiting clears it; re-enter it when editing another page.
No separate subscription or new hosting service is added.

Saves update the GitHub site, not the separate laptop/TryCloudflare data copy.
If another editor or Pages CMS changes the same file, the save is rejected instead of silently overwriting it. The draft remains visible. Copy important unsaved text before discarding and reloading.
A save involving several files can publish earlier files even if a later file fails. The status identifies partial saves; remaining changes stay unsaved.

FIRST-TIME KEY SETUP (if your posting desk is not installed yet)
Go to https://github.com/settings/personal-access-tokens/new
Use a fine-grained token with resource owner vivianongjy, only repository vivianongjy.github.io, and Contents = Read and write. Choose an expiration date, generate it, and paste it only into the website's sign-in box. Keep it private.
